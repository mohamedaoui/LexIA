Organisation du travail en solo

  • Chaque sprint traite d'abord le backend, puis le frontend qui le consomme, afin d'éviter les blocages.
  • Auto-revue de code via Pull Requests GitHub avant chaque fusion sur la branche principale.
  • Documentation technique et rapport final rédigés au fil des sprints.
  • Bilan hebdomadaire écrit (30 min) : avancement, blocages, objectifs du sprint suivant.

3Méthodologie de travail

Le projet suit une approche itérative inspirée de Scrum, adaptée à un développeur seul. Huit sprints d'une semaine, chacun avec un objectif clair et des livrables définis.

PratiqueApplication dans LexIA
Sprint hebdomadaire1 semaine = 1 sprint avec objectif et livrable définis
Point quotidien10 min chaque matin : tâches du jour et blocages
Definition of DoneCode versionné sur GitHub + tests passants + fonctionnalité démontrée
Backlog de tâchesGitHub Issues / GitHub Projects avec priorités
Revue de sprintDémonstration de la fonctionnalité en fin de semaine
RétrospectiveBilan 15 min : ce qui a fonctionné / ce qu'on améliore

RisqueProb.ImpactPlan de mitigation

R2 — Retard sur une fonctionnalité critiqueMoyenneÉlevéPriorisation MoSCoW · Réduire la portée d'une feature non critique plutôt que bloquer le jalon

R5 — Charge de travail élevée (réalisateur unique)MoyenneÉlevéBacklog priorisé · Réutilisation de composants existants · Automatisation (CI, Docker) pour gagner du temps
R6 — Perte ou corruption de la base de donnéesFaibleÉlevéSauvegardes PostgreSQL automatiques · Docker volumes persistants · Migrations versionnées
R7 — Manque de temps en fin de projetMoyenneMoyenBuffer de 2 jours en S8 · Livrer une version réduite mais fonctionnelle
R8 — Failles de sécurité (injection, XSS)FaibleÉlevéProtection native Django (CSRF/XSS) · DRF validation · Audit sécurité en S7

11Conclusion

Ce plan couvre 8 sprints, 6 jalons et 21 livrables, tous réalisés par Mohamed Aouijil. Le dépôt est séparé en trois parties — backend (API et IA), frontend (interface) et data (corpus juridique) — ce qui permet d'avancer couche par couche et de garder un rythme de livraison régulier.

Les 8 risques identifiés ont chacun un plan de mitigation concret, y compris la charge de travail propre à un projet individuel. Les critères de réussite sont mesurables et couvrent les dimensions fonctionnelles, techniques et qualitatives du projet.

La stack Django 5 + DRF + React 18 + PostgreSQL + LangChain + Docker reste la colonne vertébrale technique, cohérente avec le cahier des charges v1.1.
